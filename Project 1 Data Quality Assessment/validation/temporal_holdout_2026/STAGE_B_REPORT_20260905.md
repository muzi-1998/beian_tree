# 后续108天验证：阶段B专家执行报告

日期：2026-09-05。范围：旧数据资产恢复、历史重放、时间证据审计和独立修正候选。

## 结论

**数据可以接入，但暂不能把旧入口直接用于108天的锁定评分。** 已按研究方案推进
阶段B，发现了必须先处理的时间依赖问题。新期DO/ORP分布、regime、质量分数和
检出性能没有开启；没有在新期调阈值、重新选peer、更新D5支持或改写原release。

研究者已确认：14支探头的位置、标签、量程及探头本体未变化；年度分钟文件只
对齐时间轴，未填补原始空值。声明保存在 `source_attestation.yaml`。这支持输入
延续性，但不代替独立运维日志，也不能从对齐后的时钟反推原始重复/乱序为零。

## 发现与修正

### 1. D2缺口证据使用了未来信息

原长缺口标记先看完整缺失段长度，再回填到缺口最初几分钟；原P95使用下一分钟
判断结束，且可能把数组末端尚未结束的缺口当成完成事件。合成32min缺口追加尾段
后，14通道各有2个过去分钟的long-gap标记改变、1个过去小时的P95改变。

已新增独立候选：缺口累积到第6分钟才标长缺口，完成长度在恢复观测时入账；
评分前保留原始空值，不插值，不把原始时间戳不可观察指标赋满分，未结束小时
不发布。门槛、映射、权重不变。候选flags、窗口统计和Strict输出通过合成前缀测试。

旧期配对审计采用**两臂相同的原始时间戳不可观察合同**，不是与含原始源审计的
正式D2直接比较：85,694 sensor-hours中仅3小时D2_total改变，最大差0.00612；
Veto没有改变。Q_GS/P95局部差异保留在逐项表。Sensitive peer路线、状态checkpoint
及全场景切块测试仍未完成，不能宣告完整D2冻结入口就绪。

### 2. D4全段变点去重会改变过去评分

原代码虽限制候选变点右侧12h观察时间，却先对整段候选聚类并选最强代表。
未来候选可替换或压掉过去代表。确定性三水平目标、稳定reference反例中，
追加尾段使7个已过去时刻的Q_cp从2变5。

已新增严格as-of候选：先限定当时可得候选，再执行原24h去重，保留原KS统计门槛、
6h扫描步长、12h相邻段、7d辅助窗口和Q_cp评分表。该候选与逐时独立历史截断
重算oracle一致，合成前缀和保留历史的日切块调用一致，不回改过去输出。

完整旧期影响审计：

- 仅修正去重、仍用原标签时钟：8,869 / 42,847个Q_cp改变。
- 再加入窗口实际可获得时钟：相对前一步有824个Q_cp改变。
- 两项合并相对原版：9,245 / 42,847，约21.58%。前两项计数不相加，改变集合有重叠。
- 其他三项子分、映射、权重和D2/support门控固定时，1,940 / 42,371个共同可评价
  pair-hour跨越D4=3边界，约4.58%；DO14为648 / 6,045，约10.72%。

这是CP单因素旧期敏感性，**不是重新发布的D4/DQR最终数值，也不是全部变化都能
归因于同一种现场故障**。其影响足以要求正式新期推断采用经核验的因果修正版本，
并单独保留旧回顾性release。不能为保持原结果而保留未来依赖，也不能把候选
改善后的分数当成方法性能提高。

### 3. D5时间标签不是可获得时刻

10min快照以左端标记，00:00快照使用00:00–00:09。因此当前24h滚动结果实际涵盖
标签前23h50min至标签后10min，不能在00:00就宣称已知。新增区间合同和Gate
选择测试，显式区分标签、覆盖区间、available_at、valid_until。

D1/D2小时开始标签至少等待该小时结束；D4标签为末小时开始也至少+60min；
D3已用2h窗口结束标签。以上均不含上游转换/计算延迟。DQR正式as-of接合和
1.1短缺口修补的延迟合同尚未接通，不能只移动图上的时间轴就声称在线性解决。
